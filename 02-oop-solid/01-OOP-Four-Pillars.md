# چهار ستون شیءگرایی

## ۱. Encapsulation — کپسوله‌سازی

**تعریف:** پنهان کردن وضعیت داخلی و کنترل دسترسی از طریق متدها و property های عمومی.

**چرا مهم است؟** چون کلاس باید خودش تضمین کند همیشه در وضعیت معتبری باشد.

```csharp
public class BadAccount
{
    public decimal Balance;    // ❌ هر کسی می‌تواند بنویسد Balance = -1000
}
```

با فیلد عمومی، هیچ کنترلی روی داده نداری. کسی می‌تواند موجودی را منفی کند و کلاس تو در وضعیت غیرممکنی قرار می‌گیرد.

```csharp
public class BankAccount
{
    private decimal _balance;
    public decimal Balance => _balance;     // فقط خواندنی

    public void Withdraw(decimal amount)
    {
        if (amount > _balance)
            throw new InvalidOperationException("موجودی کافی نیست");
        _balance -= amount;
    }
}
```

حالا هر تغییری از فیلتر قوانین رد می‌شود.

**اصطلاح فنی‌اش:** به قانونی که همیشه باید برقرار باشد (مثلاً «موجودی هرگز منفی نیست») می‌گویند **invariant**. کپسوله‌سازی ابزار حفاظت از invariant هاست.

**نکته:** فقط گذاشتن `{ get; set; }` روی همه‌چیز کپسوله‌سازی نیست. اگر setter عمومی بگذاری و هیچ اعتبارسنجی نکنی، عملاً همان فیلد عمومی است با ظاهر متفاوت.

## ۲. Inheritance — وراثت

**تعریف:** کلاس فرزند ویژگی‌ها و رفتارهای پدر را به ارث می‌برد.

**فایده:** حذف کد تکراری. رفتار مشترک یک بار در پدر نوشته می‌شود.

```csharp
public abstract class Vehicle
{
    public string Plate { get; }
    public virtual string Start() => "موتور روشن شد";   // مشترک
    public abstract decimal TollFee();                   // اجباری برای فرزند
}
```

**هشدار مهم:** وراثت رابطه‌ای خیلی محکم است. فرزند به جزئیات پدر وابسته می‌شود و تغییر در پدر می‌تواند همه فرزندان را بشکند.

**تست درستی:** فقط وقتی وراثت درست است که رابطه **«هست»** (is-a) واقعاً برقرار باشد. کامیون **یک** وسیله نقلیه **است** ✓. حساب پس‌انداز **یک** لاگر **نیست** ✗.

## ۳. Polymorphism — چندریختی

**تعریف:** یک رابط، چند پیاده‌سازی. یک فراخوانی، رفتارهای متفاوت.

```csharp
foreach (var v in vehicles)
    total += v.TollFee();    // برای هر نوع، نسخه خودش اجرا می‌شود
```

این متد نمی‌داند `v` ماشین است یا کامیون یا نوعی که فردا اضافه می‌شود. **و لازم هم نیست بداند.**

### دو نوع Polymorphism

**Compile-time (Overloading)** — چند متد هم‌نام با امضای متفاوت:
```csharp
Add(int, int)
Add(double, double)
Add(int, int, int)
```
کامپایلر بر اساس نوع آرگومان‌ها تصمیم می‌گیرد کدام صدا زده شود.

**Run-time (Overriding)** — بازنویسی متد `virtual` در فرزند. تصمیم در زمان اجرا بر اساس نوع واقعی آبجکت گرفته می‌شود.

**اینجا همان تله `new` در برابر `override` است** که در فایل `01-csharp/03` توضیح داده شد — با `new` تصمیم در زمان کامپایل گرفته می‌شود، نه زمان اجرا.

## ۴. Abstraction — انتزاع

**تعریف:** نمایش فقط چیزهای ضروری و پنهان کردن پیچیدگی پیاده‌سازی.

```csharp
public interface IEmailSender
{
    void Send(string to, string subject, string body);
}
```

کدی که از این استفاده می‌کند، نمی‌داند پشت صحنه SMTP است یا SendGrid یا یک صف پیام. **و این خوب است** — چون فردا می‌توانی پیاده‌سازی را عوض کنی بدون اینکه هیچ‌جای دیگری تغییر کند.

### تفاوت Abstraction و Encapsulation

این سوال را برای جدا کردن حفظیات از فهم می‌پرسند:

| | Encapsulation | Abstraction |
|---|---|---|
| چه چیزی | پنهان کردن **داده** | پنهان کردن **پیچیدگی** |
| در چه سطحی | پیاده‌سازی (private/public) | طراحی (interface/abstract) |
| سوال | «چطور از داده محافظت کنم؟» | «چه چیزی را باید نشان بدهم؟» |

**یک جمله:** Encapsulation یعنی «چطور» را قایم کن، Abstraction یعنی فقط «چه» را نشان بده.

## Composition در برابر Inheritance

اصل معروف: **«ترکیب را به وراثت ترجیح بده»** (Favor composition over inheritance)

```csharp
// ❌ وراثت نامناسب
public class SavingsAccount : Logger { }

// ✅ ترکیب
public class SavingsAccount
{
    private readonly ILogger _logger;      // has-a
    public SavingsAccount(ILogger logger) => _logger = logger;
}
```

**چرا ترکیب بهتر است؟**
- انعطاف بیشتر — می‌توانی در زمان اجرا رفتار را عوض کنی
- وابستگی کمتر — تغییر در `Logger` این کلاس را نمی‌شکند
- تست‌پذیری — می‌توانی یک لاگر ساختگی تزریق کنی
- بدون محدودیت تک‌ارث‌بری

**قاعده ساده:** اگر رابطه **«هست»** است → وراثت. اگر **«دارد»** است → ترکیب.

## سوال احتمالی مصاحبه

> «چرا در C# ارث‌بری چندگانه وجود ندارد؟»

**جواب:** به‌خاطر **مسئله الماس** (Diamond Problem). اگر کلاس D از B و C ارث ببرد و هر دو از A، و هر دو متد `M()` را به شکل متفاوتی override کرده باشند، معلوم نیست D کدام را باید بگیرد.

C# این ابهام را با اجازه دادن فقط به یک کلاس پایه حل کرده، ولی چون interface **وضعیت و پیاده‌سازی ندارد** (تا C# 7)، پیاده‌سازی چند interface هیچ ابهامی نمی‌سازد.
